# 다수의 테이블 제어하기

## 다수의 테이블 조회

- 실제 데이터베이스는 여러 개의 테이블이 서로 연결되어 동작한다.
- 여러 테이블을 조합하여 필요한 정보를 한 번에 조회할 수 있다.
- GROUP BY, HAVING, JOIN을 이용하여 데이터를 분석하고 연결한다.

---

## GROUP BY

### GROUP BY
- 같은 값을 가진 데이터들을 하나의 그룹으로 묶는 기능
- 집계 함수(COUNT, SUM, AVG, MAX, MIN)와 함께 자주 사용

### 회원별 대여 횟수 조회

```sql
SELECT user_id, COUNT(*)
FROM rental
GROUP BY user_id;
```

### 결과 예시

| user_id | COUNT(*) |
|----------|----------|
| 1 | 2 |
| 3 | 1 |

- user_id가 같은 데이터끼리 그룹화
- 각 회원의 대여 횟수를 확인 가능

---

## GROUP BY와 집계 함수

### 합계 구하기

```sql
SELECT user_id, SUM(컬럼명)
FROM rental
GROUP BY user_id;
```

### 평균 구하기

```sql
SELECT user_id, AVG(컬럼명)
FROM rental
GROUP BY user_id;
```

### 최댓값 구하기

```sql
SELECT user_id, MAX(컬럼명)
FROM rental
GROUP BY user_id;
```

### 최솟값 구하기

```sql
SELECT user_id, MIN(컬럼명)
FROM rental
GROUP BY user_id;
```

- 그룹별 통계 정보를 계산할 수 있다.

---

## HAVING

### HAVING
- GROUP BY로 생성된 그룹에 조건을 적용
- WHERE는 행(Row)에 조건 적용
- HAVING은 그룹(Group)에 조건 적용

### 2회 이상 대여한 회원 조회

```sql
SELECT user_id, COUNT(*)
FROM rental
GROUP BY user_id
HAVING COUNT(user_id) > 1;
```

### 실행 순서

```sql
FROM
→ GROUP BY
→ HAVING
→ SELECT
```

- 먼저 그룹을 만든 후 그룹 조건을 검사

## INNER JOIN

### INNER JOIN
- 두 테이블에서 공통으로 존재하는 데이터만 조회

### 기본 문법

```sql
SELECT *
FROM rental
INNER JOIN user;
```

- 단순 연결만 수행
- 실제로는 연결 조건이 필요

### JOIN이 필요한 이유

- rental 테이블 : 대여 정보
- user 테이블 : 회원 정보

두 테이블을 연결하면

- 대여 기록
- 회원 이름
- 이메일

등을 한 번에 조회할 수 있다.

---

## INNER JOIN + ON

### ON
- 어떤 컬럼을 기준으로 연결할지 지정

### 기본 문법

```sql
SELECT *
FROM rental
INNER JOIN user
ON user.id = rental.user_id;
```

### 의미

```text
user.id
=
rental.user_id
```

- 회원 번호가 같은 데이터끼리 연결
- 공통 데이터만 결과에 포함

### 결과 예시

| rental_id | user_id | book_id | name |
|------------|------------|------------|------------|
| 1 | 1 | 1000 | chanhwan |
| 2 | 1 | 1001 | chanhwan |
| 3 | 3 | 1004 | hyungon |

---

## LEFT JOIN

### LEFT JOIN
- 왼쪽 테이블의 모든 데이터를 유지
- 오른쪽 테이블과 일치하는 값만 연결

### 기본 문법

```sql
SELECT *
FROM user
LEFT JOIN rental
ON user.id = rental.user_id;
```

### 특징

- user 테이블의 모든 회원 출력
- 대여 기록이 없는 회원도 포함

### 결과 예시

| user_id | name | rental_id |
|----------|----------|----------|
| 1 | chanhwan | 1 |
| 1 | chanhwan | 2 |
| 2 | haesol | NULL |
| 3 | hyungon | 3 |

### INNER JOIN과 비교

| JOIN | 결과 |
|--------|--------|
| INNER JOIN | 겹치는 데이터만 |
| LEFT JOIN | 왼쪽 테이블 전체 |

---

## RIGHT JOIN

### RIGHT JOIN
- 오른쪽 테이블의 모든 데이터를 유지
- 왼쪽 테이블과 일치하는 값만 연결

### 기본 문법

```sql
SELECT *
FROM user
RIGHT JOIN rental
ON user.id = rental.user_id;
```

### 특징

- rental 테이블의 모든 대여 기록 출력
- 회원 정보가 없는 대여 기록도 포함

### 결과 예시

| id | name | rental_id |
|------|------|------|
| 1 | chanhwan | 1 |
| 1 | chanhwan | 2 |
| NULL | NULL | 3 |

### LEFT JOIN과 비교

| JOIN | 결과 |
|--------|--------|
| LEFT JOIN | 왼쪽 테이블 전체 |
| RIGHT JOIN | 오른쪽 테이블 전체 |

---

## JOIN 정리

### INNER JOIN

```sql
SELECT *
FROM A
INNER JOIN B
ON A.id = B.id;
```

- 두 테이블에서 공통으로 존재하는 데이터만 조회

### LEFT JOIN

```sql
SELECT *
FROM A
LEFT JOIN B
ON A.id = B.id;
```

- A 테이블 전체 조회

### RIGHT JOIN

```sql
SELECT *
FROM A
RIGHT JOIN B
ON A.id = B.id;
```

- B 테이블 전체 조회

---

## 핵심 정리

- GROUP BY는 같은 값을 가진 데이터를 그룹화한다.
- COUNT, SUM, AVG, MAX, MIN과 함께 자주 사용된다.
- HAVING은 그룹에 조건을 적용한다.
- INNER JOIN은 두 테이블의 공통 데이터만 조회한다.
- ON은 테이블을 연결할 기준 컬럼을 지정한다.
- LEFT JOIN은 왼쪽 테이블의 모든 데이터를 유지한다.
- RIGHT JOIN은 오른쪽 테이블의 모든 데이터를 유지한다.
- JOIN을 사용하면 여러 테이블의 정보를 한 번에 조회할 수 있다.

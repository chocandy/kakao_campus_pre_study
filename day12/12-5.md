# Promise

# Promise란?

## Promise가 필요한 이유

기본적인 비동기 처리(setTimeout 등)는 결과를 바로 활용하기 어렵다.

예시

```javascript
let name = "Elice";

setTimeout(() => {
    name = "Hellobit";
}, 2000);

console.log(name);
```

결과

```text
Elice
```

이유

- setTimeout의 콜백은 나중에 실행됨
- 현재 코드는 먼저 종료됨

---

## 에러 처리 문제

```javascript
try {

    setTimeout(() => {
        throw new Error("Error");
    }, 1000);

} catch (err) {

    console.log(err);

}
```

문제점

- try-catch로 잡히지 않음
- 에러가 비동기적으로 발생하기 때문

---

## Promise의 역할

Promise는

- 비동기 결과 처리
- 비동기 에러 처리

를 쉽게 할 수 있도록 제공되는 객체

---

# Promise 생성

## 기본 문법

```javascript
const promise =
    new Promise(
        (resolve, reject) => {

        }
    );
```

특징

- new Promise() 사용
- 콜백 함수 필수
- resolve, reject 제공

---

# resolve와 reject

## resolve()

비동기 작업 성공

```javascript
resolve(data);
```

---

## reject()

비동기 작업 실패

```javascript
reject(error);
```

---

## 예시

```javascript
const promise =
    new Promise(
        (resolve, reject) => {

            const score = 80;

            if (score >= 60) {

                resolve(score);

            } else {

                reject("Fail");

            }

        }
    );
```

---

# Promise 상태(State)

Promise는 세 가지 상태를 가짐

| 상태 | 의미 |
|--------|--------|
| pending | 대기 |
| fulfilled | 성공 |
| rejected | 실패 |

---

## pending

Promise 생성 직후 상태

```javascript
const promise =
    new Promise(() => {});
```

상태

```text
pending
```

---

## fulfilled

resolve 호출 시

```javascript
resolve(100);
```

상태 변화

```text
pending
↓
fulfilled
```

---

## rejected

reject 호출 시

```javascript
reject("error");
```

상태 변화

```text
pending
↓
rejected
```

---

# Promise 처리

## then()

비동기 작업 완료 후 실행

```javascript
promise.then(
    successCallback,
    failCallback
);
```

---

## 성공 처리

```javascript
promise.then(result => {

    console.log(result);

});
```

예시

```javascript
resolve(100);
```

↓

```text
100
```

---

## 실패 처리

```javascript
promise.then(

    result => {
        console.log(result);
    },

    error => {
        console.log(error);
    }

);
```

---

# catch()

## catch란?

실패 처리 전용 메서드

```javascript
promise.catch(error => {

    console.log(error);

});
```

예시

```javascript
reject("Fetch Failed");
```

↓

```text
Fetch Failed
```

---

# finally()

## finally란?

성공 여부와 관계없이 항상 실행

```javascript
promise.finally(() => {

    console.log("끝");

});
```

특징

- fulfilled
- rejected

모두 실행

---

# Promise Chaining

## 메서드 체이닝

Promise 메서드는 Promise를 반환

따라서 연속 호출 가능

```javascript
promise
    .then(...)
    .catch(...)
    .finally(...);
```

실제 사용 예시

```javascript
fetchData()

    .then(data => {

        console.log(data);

    })

    .catch(error => {

        console.log(error);

    })

    .finally(() => {

        console.log("finish");

    });
```

---

# Promise.resolve()

## resolve 상태 Promise 생성

```javascript
Promise.resolve(100);
```

동일 표현

```javascript
new Promise(resolve => {

    resolve(100);

});
```

---

# Promise.reject()

## reject 상태 Promise 생성

```javascript
Promise.reject("error");
```

동일 표현

```javascript
new Promise((resolve, reject) => {

    reject("error");

});
```

---

# Promise.all()

## Promise.all이란?

여러 Promise를 동시에 처리

```javascript
Promise.all([
    promise1,
    promise2,
    promise3
]);
```

---

## 모든 작업 성공 시

```javascript
Promise.all([
    p1,
    p2,
    p3
])

.then(result => {

    console.log(result);

});
```

결과

```javascript
[
    result1,
    result2,
    result3
]
```

특징

- 모든 Promise가 resolve 되어야 함
- 결과는 배열 반환

---

## Fail-Fast

하나라도 실패하면 즉시 실패

```javascript
Promise.all([
    p1,
    p2,
    p3
]);
```

↓

```text
p2 reject
```

↓

```text
전체 reject
```

특징

- 나머지 결과 기다리지 않음
- 가장 먼저 실패한 에러 반환

---

# Promise.allSettled()

## allSettled란?

모든 Promise가 끝날 때까지 대기

```javascript
Promise.allSettled([
    p1,
    p2,
    p3
]);
```

특징

- 성공/실패 관계없이 전부 대기
- 일부 실패 허용

---

## 반환 형태

성공

```javascript
{
    status: "fulfilled",
    value: data
}
```

실패

```javascript
{
    status: "rejected",
    reason: error
}
```

---

# Promise.all vs Promise.allSettled

| 구분 | Promise.all | Promise.allSettled |
|--------|--------|--------|
| 실패 발생 | 즉시 종료 | 끝까지 대기 |
| 반환값 | 성공 결과 배열 | 상태 객체 배열 |
| 특징 | Fail-Fast | Wait-All |
| 사용 시점 | 모두 성공해야 의미 있음 | 일부 실패 허용 |

# 마이크로태스크 큐(Microtask Queue)

## 문제

```javascript
console.log(1);

setTimeout(() => {
    console.log(4);
}, 0);

Promise.resolve()
    .then(() => {
        console.log(3);
    });

console.log(2);
```

결과

```text
1
2
3
4
```

---

## 왜 3이 먼저 실행될까?

브라우저에는 두 개의 큐가 존재

```text
Microtask Queue
Task Queue
```

---

# 우선순위

```text
Call Stack
↓
Microtask Queue
↓
Task Queue
```

Microtask Queue가 더 우선순위 높음

---

# Microtask Queue

저장되는 작업

- Promise
- Ajax(Fetch)

---

# Task Queue

저장되는 작업

- setTimeout
- setInterval
- 이벤트 핸들러

# 핵심 정리

- Promise는 비동기 결과와 에러 처리를 위한 객체
- Promise는 pending, fulfilled, rejected 상태를 가짐
- resolve()는 성공, reject()는 실패를 의미
- then()은 성공/실패 후 처리
- catch()는 실패 처리
- finally()는 성공 여부와 관계없이 실행
- Promise 메서드는 Promise를 반환하므로 체이닝 가능
- Promise.resolve()는 즉시 성공하는 Promise 생성
- Promise.reject()는 즉시 실패하는 Promise 생성
- Promise.all()은 모든 Promise 성공 시 결과 반환
- Promise.all()은 하나라도 실패하면 즉시 reject(Fail-Fast)
- Promise.allSettled()는 성공/실패와 관계없이 모두 완료될 때까지 대기
- Promise 관련 작업은 Microtask Queue에 저장
- Microtask Queue는 Task Queue보다 우선순위가 높음
- 따라서 Promise 콜백은 setTimeout 콜백보다 먼저 실행됨

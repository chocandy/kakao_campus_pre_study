# 네트워크 핵심 개념

## 네트워크란?

네트워크는 두 대 이상의 컴퓨터가 데이터를 주고받을 수 있도록 연결된 통신 구조이다.  
인터넷은 전 세계의 여러 네트워크가 서로 연결된 거대한 네트워크 형태로 구성된다.

네트워크 통신에서는:
- 요청을 보내는 클라이언트(Client)
- 요청을 처리하는 서버(Server)
- 데이터를 주고받기 위한 규칙인 프로토콜(Protocol)

이 함께 동작한다.

클라이언트와 서버는 물리적으로 멀리 떨어져 있어도 인터넷을 통해 데이터를 송수신할 수 있다.

---

## IP 주소

네트워크 통신에서는 데이터를 정확한 목적지까지 전달하기 위해 주소 체계가 필요하다.

IP 주소는 네트워크 상에서 장치를 식별하기 위한 고유 주소이며,
데이터 패킷의 송신지와 목적지를 구분하는 역할을 한다.

IPv4는:
- 32bit 구조
- 4개의 옥텟으로 구성
- 약 43억 개 주소 제공

형태를 가진다.

예시:
- `192.168.0.1`

IP 주소는:
- 네트워크 ID
- 호스트 ID

영역으로 나뉘며,
서브넷 마스크를 통해 구분된다.

IPv4 주소 부족 문제로 인해 IPv6가 등장하였다.

IPv6는:
- 128bit 주소 체계
- 16진수 사용
- 훨씬 많은 주소 제공
- 자동 주소 구성 및 보안 기능 강화

특징을 가진다.

## DNS

IP 주소는 숫자로 이루어져 있어 사람이 기억하기 어렵다.

DNS(Domain Name System)는:
- 도메인 이름
- 실제 IP 주소

사이의 변환을 처리하는 시스템이다.

예시:
- `www.elice.io`
→ `52.xxx.xxx.xxx`

브라우저에 도메인을 입력하면 DNS 서버가 해당 도메인의 실제 IP 주소를 찾아 통신을 수행한다.

## Port 번호

하나의 컴퓨터에서는 여러 프로그램과 서비스가 동시에 실행된다.

IP 주소만으로는 어떤 프로그램과 통신해야 하는지 구분할 수 없기 때문에 Port 번호를 함께 사용한다.

포트 번호는:
- 특정 애플리케이션 또는 서비스 식별
- 동일한 IP 내 서비스 구분

역할을 수행한다.

표현 방식:
- `IP주소:포트번호`
- 예시: `192.168.0.10:80`

포트 번호 범위:
- `0 ~ 65535`

대표적인 Well-known Port:
- 21 → FTP
- 22 → SSH
- 53 → DNS
- 80 → HTTP
- 443 → HTTPS

## 네트워크의 종류

네트워크는 연결 범위에 따라 구분된다.

### PAN
개인 장치 간 연결  
예:
- 스마트워치
- 블루투스 이어폰

### LAN
제한된 지역 내 네트워크  
예:
- 학교
- 사무실

### MAN
도시 규모 네트워크  
예:
- 공공 와이파이
- 캠퍼스 네트워크

### WAN
넓은 지역을 연결하는 네트워크  
대표 사례:
- 인터넷

## 네트워크 토폴로지

토폴로지는 네트워크 장치들의 연결 구조를 의미한다.

### Bus Topology
- 하나의 중앙 케이블 공유
- 설치 비용 저렴
- 장애 발생 시 전체 영향 가능

### Star Topology
- 중앙 허브/스위치 기반
- 관리 용이
- 중앙 장치 장애 시 전체 영향

### Ring Topology
- 링 형태 연결
- 데이터 충돌 감소
- 장치 장애 영향 존재

### Mesh Topology
- 모든 장치 직접 연결
- 높은 신뢰성 제공
- 구축 비용 증가

---

## 네트워크 통신 방식

### Unicast
1:1 통신 방식  
예:
- 웹 브라우징
- 파일 전송

### Multicast
1:N 특정 그룹 통신  
예:
- 라이브 스트리밍
- 온라인 강의

### Broadcast
네트워크 전체 대상 통신  
예:
- ARP 요청
- 네트워크 탐색

## TCP/IP 프로토콜

TCP/IP는 인터넷 통신의 기본 프로토콜 구조이다.

### TCP/IP 4계층

#### 응용 계층
HTTP, FTP, SMTP 등 응용 프로그램 통신 처리

#### 전송 계층
TCP, UDP 기반 데이터 전송 처리

#### 인터넷 계층
IP 기반 주소 지정 및 라우팅 수행

#### 네트워크 액세스 계층
물리적 네트워크 전송 처리

IP 프로토콜만 사용할 경우:
- 패킷 순서 보장 불가
- 패킷 손실 가능
- 재전송 기능 부재

문제가 발생할 수 있다.

---

## TCP와 UDP

### TCP
- 연결 지향 방식
- 순서 보장
- 오류 검출 및 재전송 가능
- 높은 신뢰성
- 속도 상대적으로 느림

사용 사례:
- 웹페이지
- 이메일
- 파일 전송

3-way Handshake를 통해 연결을 생성하고,
4-way Handshake를 통해 연결을 종료한다.

---

### UDP
- 비연결형 방식
- 순서 보장 없음
- 재전송 기능 없음
- 빠른 속도

사용 사례:
- 스트리밍
- 온라인 게임
- 실시간 서비스

TCP는 안정성을,
UDP는 속도와 실시간성을 중심으로 사용하는 프로토콜이다.

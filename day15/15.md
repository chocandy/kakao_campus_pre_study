
# GitHub 협업

## GitHub 협업의 필요성

- Git은 로컬 환경에서 버전 관리를 수행하는 도구이고, GitHub는 원격 저장소를 제공하는 협업 플랫폼이다.
- 여러 개발자가 동시에 작업할 경우 코드를 한 곳에서 관리하고 변경사항을 공유할 수 있는 원격 저장소가 필요하다.
- Git의 분산 버전 관리 구조를 기반으로 각 개발자는 독립적으로 작업한 뒤 변경사항을 공유할 수 있다.
- 브랜치를 활용하여 서로 영향을 주지 않고 병렬 개발이 가능하다.
- Pull Request를 통해 코드 리뷰와 협업 과정을 기록할 수 있다.

---

# Git과 GitHub

## Git

- 로컬 환경에서 버전 관리를 수행하는 도구
- 커밋, 브랜치, 병합 기능 제공
- 프로젝트 변경 이력을 관리

## GitHub

- Git 저장소를 온라인에서 관리하는 플랫폼
- 협업 및 코드 공유 기능 제공
- Pull Request, Issue, Wiki 등의 기능 제공

---

# GitHub 협업 구성 요소

## Repository

- 프로젝트 전체를 저장하는 저장소
- 코드, 브랜치, 커밋 이력 등을 포함

## Branch

- 독립적인 작업 공간
- 기능 개발, 버그 수정 등을 분리하여 작업 가능

## Pull Request(PR)

- 브랜치 작업 내용을 다른 브랜치에 병합하기 위한 요청
- 코드 리뷰와 협업의 핵심 절차

## Issue

- 기능 요청, 버그, 작업 내용을 기록하고 관리
- 담당자 지정 및 진행 상황 추적 가능

## Wiki

- 프로젝트 문서 관리
- 개발 환경 설정, 규칙, 아키텍처 등을 기록

# GitHub 저장소 생성

## Repository 생성 시 설정 항목

- Repository Name
- Description
- Public / Private 설정
- README 생성 여부
- .gitignore 설정
- License 설정

### README

- 프로젝트 설명 문서
- 설치 방법, 사용법, 개발 규칙 등을 기록
- Markdown 형식 사용

### .gitignore

- Git이 추적하지 않을 파일 지정
- 빌드 결과물, 설정 파일, 비밀번호 파일 등을 제외

### License

- 소프트웨어 사용 및 배포 규칙 정의
- 오픈소스 프로젝트에서 중요

# 원격 저장소 연결

## 저장소 복제

```bash

```

원격 저장소를 로컬로 복제

---

## 기존 프로젝트 연결

```bash
git init

git remote add origin <repository-url>

git push -u origin main
```

# Git Flow

## 주요 브랜치

### main

- 배포 버전 관리

### develop

- 다음 버전 개발 브랜치

### feature

- 기능 개발 브랜치

### release

- 배포 준비 브랜치

### hotfix

- 긴급 수정 브랜치

---

## 개발 흐름

```text
develop
 ↓
feature
 ↓
develop
 ↓
release
 ↓
main
```

긴급 수정

```text
main
 ↓
hotfix
 ↓
main
 ↓
develop
```

# 브랜치 병합 전략

## Merge Commit

- 모든 커밋 이력 유지
- 히스토리가 복잡해질 수 있음

## Squash and Merge

- 여러 커밋을 하나로 압축
- 히스토리가 단순해짐

## Rebase and Merge

- 선형적인 히스토리 유지
- 충돌 해결이 상대적으로 복잡

# Git LFS

## Git LFS란?

Large File Storage

- 대용량 파일 관리를 위한 Git 확장 기능
- Git에는 포인터만 저장
- 실제 파일은 별도 저장소에 관리

---

## 사용 이유

- 저장소 용량 감소
- Clone 속도 향상
- 대용량 파일 버전 관리 가능

예시

- mp4
- psd
- zip
- 대용량 csv

# Merge Conflict

## 충돌 발생 원인

- 같은 파일의 같은 부분을 동시에 수정
- 삭제된 파일을 다른 브랜치에서 수정

---

## 충돌 마커

```text
<<<<<<< HEAD

=======

>>>>>>> branch-name
```

## VSCode 충돌 해결 옵션

### Accept Current Change

현재 브랜치 유지

### Accept Incoming Change

병합 대상 브랜치 유지

### Accept Both Changes

양쪽 모두 유지

### Compare Changes

차이 비교 후 직접 수정

# 핵심 정리

- Git은 버전 관리 도구, GitHub는 협업 플랫폼
- Repository는 프로젝트 저장소
- Branch를 통해 독립적인 개발 가능
- Pull Request를 통해 코드 리뷰와 병합 수행
- Issue와 Wiki를 활용해 프로젝트 관리 가능
- Git Flow는 실무에서 자주 사용하는 브랜치 전략
- Merge, Squash, Rebase 방식의 병합 전략 존재
- Git LFS는 대용량 파일 관리를 위한 기능
- stash, reflog, cherry-pick 등 다양한 고급 Git 기능 제공
- 협업 시 최신 코드 Pull과 충돌 관리가 중요

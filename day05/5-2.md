# 데이터베이스 구성하기

## 1. 제약 조건(Constraint)

### 제약 조건
- 잘못된 데이터 입력을 방지하기 위한 규칙
- 데이터의 무결성을 유지하기 위해 사용

### NOT NULL
- NULL 값 입력 불가
- 반드시 값이 존재해야 함
- 값을 입력하지 않으면 에러 발생
- 별도 지정이 없으면 기본적으로 NULL 허용

```sql
CREATE TABLE customer(
    id VARCHAR(30),
    name VARCHAR(30) NOT NULL
);
```

### UNIQUE
- 중복 값 허용 불가
- 동일한 값이 존재하면 에러 발생
- NULL 값은 중복되어도 허용됨

```sql
CREATE TABLE customer(
    id VARCHAR(30) UNIQUE,
    name VARCHAR(30)
);
```

### DEFAULT
- 값을 입력하지 않았을 때 기본값 자동 설정

```sql
CREATE TABLE customer(
    address VARCHAR(30) DEFAULT 'No Address'
);
```

### CHECK
- 특정 조건을 만족하는 값만 허용
- 조건을 만족하지 않으면 에러 발생

```sql
CREATE TABLE customer(
    age INT CHECK(age >= 19)
);
```

### CONSTRAINT
- 제약 조건에 이름을 부여 가능
- 유지보수 시 관리하기 편함

```sql
CREATE TABLE customer(
    id VARCHAR(30),
    age INT,

    CONSTRAINT id_unique UNIQUE(id),
    CONSTRAINT age_check CHECK(age >= 19)
);
```

### 제약 조건 조회

```sql
SELECT * FROM information_schema.table_constraints;
```

### 제약 조건 추가

```sql
ALTER TABLE customer
ADD CONSTRAINT address_unique UNIQUE(address);
```

### DEFAULT 수정

```sql
ALTER TABLE customer
ALTER address SET DEFAULT '주소 없음';
```

### 제약 조건 삭제

```sql
ALTER TABLE customer
DROP CONSTRAINT customer_chk_2;
```

### DEFAULT 삭제

```sql
ALTER TABLE customer
ALTER address DROP DEFAULT;
```

# 2. 키(Key)

## 키(Key)
- 특정 튜플을 식별하거나 정렬할 때 사용하는 속성

## 기본키(Primary Key)
- 각 튜플을 유일하게 식별하는 속성
- 중복 불가
- NULL 불가
- 테이블당 하나만 설정 가능

```sql
PRIMARY KEY
```

## 외래키(Foreign Key)
- 다른 테이블의 기본키를 참조하는 속성
- 테이블 간 관계를 연결
- 참조 대상 테이블에 없는 값은 저장 불가

```sql
FOREIGN KEY (customer_id)
REFERENCES customer(id)
```

## PRIMARY KEY / FOREIGN KEY 예시

```sql
CREATE TABLE customer(
    id VARCHAR(30) PRIMARY KEY,
    name VARCHAR(30)
);

CREATE TABLE order_history(
    customer_id VARCHAR(30),
    order_id VARCHAR(30),

    FOREIGN KEY(customer_id)
    REFERENCES customer(id)
);
```

## 후보키(Candidate Key)
- 기본키가 될 수 있는 키
- 유일성과 최소성을 만족

## 대체키(Alternate Key)
- 후보키 중 기본키로 선택되지 않은 키

## 슈퍼키(Super Key)
- 튜플을 식별할 수 있지만 최소성은 만족하지 않는 키

## 무결성 제약 조건
- 개체 무결성
  - 기본키는 NULL·중복 불가
- 참조 무결성
  - 외래키는 참조 테이블 기본키 값과 일치해야 함
- 도메인 무결성
  - 속성 값은 정의된 범위 내 값이어야 함
- NULL 무결성
  - 특정 속성은 NULL 불가
- 고유 무결성
  - 속성 값은 서로 달라야 함
- 키 무결성
  - 테이블에는 최소 하나 이상의 키 존재

# 3. 데이터 모델링

## 데이터 모델링
- 현실 세계의 데이터를 데이터베이스 구조로 표현하는 과정

## 데이터 모델 구성 요소

### 개체(Entity)
- 데이터로 표현할 대상
- 예: 회원, 킥보드

### 속성(Attribute)
- 개체가 가지는 정보
- 예: 이름, 전화번호, 브랜드

### 관계(Relationship)
- 개체 간의 연관성
- 예: 고객은 킥보드를 대여한다

## 데이터 모델링 과정

### 개념적 설계
- 현실 세계를 추상적으로 표현
- 개체와 관계 중심 설계

### 논리적 설계
- DBMS에서 사용할 스키마 설계
- 테이블 구조 정의

### 물리적 설계
- 실제 저장 구조 설계
- 저장 방식과 성능 고려

# 4. ER 다이어그램 (Peter Chen)

## ERD(Entity Relationship Diagram)
- 현실 세계 데이터를 개체와 관계 형태로 시각화한 다이어그램

## ERD 표기 방식
- Peter Chen 방식
- IE 방식

## ERD 구성 요소

| 기호 | 의미 |
|---|---|
| Entity | 개체 |
| Attribute | 속성 |
| Relationship | 관계 |
| 밑줄 속성 | 기본키 |

## 공유 킥보드 요구사항 예시
- 고객은 이름, ID, PW, 전화번호, 생년월일 입력
- 킥보드는 고유 ID 보유
- 브랜드와 연식에 따라 기본료 다름
- 대여 시 대여시간·위치·상태 기록
- 고객은 동시에 하나의 킥보드만 대여 가능

## 관계(Relationship) 종류

| 관계 | 의미 |
|---|---|
| 1 : 1 | 하나와 하나 연결 |
| 1 : N | 하나가 여러 개와 연결 |
| N : M | 다대다 관계 |

- N:M 관계는 별도 테이블로 분리
- 각 개체의 기본키를 외래키로 사용

# 5. ER 다이어그램 (IE)

## IE(Information Engineering)
- 데이터 타입과 제약 조건까지 표현 가능
- 관계를 더 구체적으로 표현 가능

## 까마귀발(Crow’s Foot) 표기법

| 기호 | 의미 |
|---|---|
| 0 또는 1 | 선택적 단일 관계 |
| 정확히 1 | 필수 단일 관계 |
| 0 이상 | 선택적 다중 관계 |
| 1 이상 | 필수 다중 관계 |

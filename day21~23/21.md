# Docker Container 기초

## Docker가 등장한 이유

- 개발 환경과 운영 환경이 달라 발생하는 문제 해결
- OS 버전, 라이브러리 버전, 설치 순서 차이로 오류 발생
- "내 컴퓨터에서는 되는데?" 문제를 해결하기 위한 기술

---

# 서버 운영의 역사

## 1. Bare Metal

- 물리 서버에 OS를 직접 설치
- Hypervisor 없음
- 성능은 가장 좋음
- 하나의 서버에 하나의 OS만 사용
- 자원 활용률이 낮음

---

## 2. Virtual Machine (VM)

- Hypervisor 위에서 여러 개의 Guest OS 실행
- 각 VM이 독립적인 OS 보유
- 서로 완전히 격리
- 다양한 운영체제 사용 가능

### 장점

- 높은 격리성
- Windows와 Linux 동시 사용 가능

### 단점

- Guest OS까지 포함되어 무거움
- 부팅 속도가 느림
- CPU, Memory 오버헤드 존재

---

## 3. Container

- Host OS의 커널을 공유
- 실행 환경만 독립적으로 분리

### 장점

- 매우 가벼움
- 빠른 실행
- 리소스 효율적 사용
- 하나의 OS에서 수십~수백 개 실행 가능
- DevOps, MSA의 핵심 기술

### 단점

- VM보다 격리 수준이 낮음
- Host Kernel을 공유

---

# 컨테이너 핵심 기술

## chroot

파일 시스템 격리

- 가짜 Root(/) 생성
- 파일 시스템만 분리
- 프로세스 보호는 불가능

---

## namespace

프로세스 및 시스템 자원 격리

분리 가능한 것

- PID
- Network
- Hostname
- Process

각 컨테이너가 독립된 환경처럼 동작

---

## cgroup

리소스 제한 기능

제한 가능한 자원

- CPU
- Memory
- Disk I/O
- Network
- Process 수

컨테이너 하나가 폭주해도 전체 서버 보호

---

## 컨테이너 구성

```
chroot
   +
namespace
   +
cgroup
   =
Container
```

# VM vs Container

|구분|VM|Container|
|---|---|---|
|가상화|하드웨어|OS|
|OS|Guest OS 포함|Host Kernel 공유|
|속도|느림|빠름|
|용량|GB|MB|
|격리|높음|상대적으로 낮음|

---

# Docker란?

Docker는

> 애플리케이션과 실행 환경을 하나의 컨테이너로 패키징하여
어디서든 동일하게 실행할 수 있도록 해주는 오픈소스 플랫폼

---

# Docker 특징

- 애플리케이션과 라이브러리를 함께 패키징
- 환경 차이 제거
- Host Kernel 공유
- Namespace와 cgroup으로 격리

---

# Docker 장점

## Flexible

복잡한 애플리케이션도 컨테이너화 가능

## Lightweight

OS 커널 공유 → 가벼움

## Interchangeable

실행 중에도 업데이트 가능

## Portable

어디서든 동일하게 실행 가능

## Scalable

컨테이너 복제를 통한 확장 가능

# Docker 명령어

## 이미지 생성

```bash
docker build -t my-app .
```

옵션

```bash
-t            이미지 이름 지정
-f            Dockerfile 지정
--no-cache    캐시 사용 안함
--target      Multi Stage 대상 지정
```

---

## 컨테이너 실행

```bash
docker run 이미지명
```

자주 사용하는 옵션

```bash
-it        터미널 접속

-d         백그라운드 실행

--name     이름 지정

-p         포트 연결

-v         볼륨 연결

--rm       종료 시 자동 삭제
```

예시

```bash
docker run -it ubuntu:20.04 bash

docker run -d --name nginx -p 8080:80 nginx

docker run --rm ubuntu echo "Hello"
```

---

## 실행 중인 컨테이너 확인

```bash
docker ps
```

옵션

```bash
-a

-q

-n 3
```

---

## 컨테이너 삭제


## 실행 중인 컨테이너 접속

# 주요 Dockerfile 명령어

## FROM

베이스 이미지 지정

```dockerfile
FROM python:3.11
```

가장 먼저 작성

---

## COPY

파일 복사

```dockerfile
COPY . /app
```

---

## WORKDIR

작업 디렉토리 설정

```dockerfile
WORKDIR /app
```

---

## EXPOSE

컨테이너 포트 명시

```dockerfile
EXPOSE 8000
```

※ 실제 포트 오픈은 아님

실제 연결

```bash
docker run -p 8000:8000
```

---

## RUN

이미지 빌드 중 실행

```dockerfile
RUN pip install -r requirements.txt
```

---

## CMD

컨테이너 실행 시 기본 명령

```dockerfile
CMD ["python","main.py"]
```

---

## USER

실행 사용자 지정

```dockerfile
USER appuser
```

보안상 Root 사용 지양

---

# RUN / CMD 차이

|명령어|실행 시점|
|-------|----------|
|RUN|이미지 빌드|
|CMD|컨테이너 실행|
|ENTRYPOINT|항상 실행되는 명령|

---

# Docker Layer

- Dockerfile의 각 명령은 하나의 Layer 생성
- Layer는 수정 불가능
- 변경 없는 Layer는 캐시 사용

### 캐시 활용

- 변경이 적은 명령은 위쪽
- 변경이 잦은 COPY는 아래쪽

→ 빌드 속도 향상

---

# Dockerfile 작성 순서

```dockerfile
FROM

WORKDIR

COPY

RUN

EXPOSE

CMD
```

# FastAPI Dockerfile 예시

```dockerfile
FROM python:3.11

WORKDIR /app

COPY . .

RUN pip install -r requirements.txt

EXPOSE 8000

CMD ["uvicorn","main:app","--host","0.0.0.0","--port","8000"]
```

# 핵심 정리

- Docker는 실행 환경까지 함께 패키징하는 플랫폼
- Container는 Host Kernel을 공유한다.
- Container는 chroot + namespace + cgroup 기술로 구현된다.
- Image는 설계도, Container는 실행 상태이다.
- Docker 구성요소는 Client → Daemon → Image → Container이다.
- 가장 많이 사용하는 명령어는 build, run, ps, exec, rm이다.
- Dockerfile 핵심 명령어는 FROM, COPY, WORKDIR, RUN, EXPOSE, CMD이다.
- RUN은 이미지 생성 시 실행되고 CMD는 컨테이너 실행 시 실행된다.
- EXPOSE는 문서화 역할이며 실제 포트 연결은 docker run -p로 수행한다.
- Docker Layer Cache를 활용하면 빌드 속도를 크게 향상시킬 수 있다.

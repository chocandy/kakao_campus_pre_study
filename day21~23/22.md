# Docker Compose

# 환경 변수(Environment Variable)

## 환경 변수란?

- 프로그램 실행 시 사용하는 설정 값
- Docker 이미지 빌드 및 컨테이너 실행 시 사용
- 포트 번호, DB 주소, API Key 등을 관리
- Dockerfile의 `ENV` 명령어로 설정 가능
- 부모 이미지의 ENV는 자식 이미지에도 상속됨

---

## ENV 사용

```dockerfile
ENV PORT=8000
ENV DB_HOST=mysql
```

환경 변수 참조

```bash
${PORT}
```

`${VAR}` 형식을 사용하는 것이 권장됨

---

## 환경 변수 설정 방법

### Dockerfile

```dockerfile
ENV PORT=8000
```

### 이미지 빌드 시

```bash
docker build --build-arg PORT=8000
```

(ARG 사용)

### 컨테이너 실행 시

```bash
docker run -e PORT=8000
```

### env 파일 사용

```bash
docker run --env-file .env
```

---

## ENV vs ARG

|ENV|ARG|
|---|---|
|컨테이너 실행 중에도 사용|빌드 시에만 사용|
|이미지에 저장|이미지에 저장되지 않음|

---

# Docker Volume

## 컨테이너의 문제

컨테이너 삭제 시 내부 데이터도 함께 삭제된다.

→ 데이터를 영구 저장(Persistence)해야 한다.

---

## 데이터 영속화 방법

### Volume

- Docker가 직접 관리
- 성능 우수
- 가장 권장되는 방식

### Bind Mount

- Host 디렉토리 직접 연결
- 개발 환경에서 많이 사용

---

## Volume 생성

Dockerfile

```dockerfile
VOLUME /data
```

또는

```bash
docker run -v my-volume:/data
```

---

## Bind Mount

```bash
docker run -v ./data:/app/data
```

Host 폴더와 컨테이너 폴더를 연결

---

## --mount 옵션

```bash
docker run --mount type=volume,...
```

또는

```bash
docker run --mount type=bind,...
```

`-v`보다 상세한 설정 가능

---

## Volume vs Bind Mount

|Volume|Bind Mount|
|-------|----------|
|Docker가 관리|사용자가 관리|
|성능 우수|개발 시 편리|
|DB, 로그 저장|소스코드 공유|

---

# Docker Network

## Docker Network란?

컨테이너끼리 통신하기 위한 네트워크

- IP
- DNS(컨테이너 이름)

으로 통신 가능

---

## 기본 Bridge Network

컨테이너 실행 시 자동 연결

특징

- IP 통신 가능
- 컨테이너 이름(DNS) 통신 불가

---

## 사용자 정의 Network

```bash
docker network create my-network
```

같은 Network에 연결되면

- IP
- 컨테이너 이름(DNS)

모두 사용 가능

---

## 컨테이너 실행

```bash
docker run --network my-network
```

---

# 다중 컨테이너

## 개념

하나의 서비스를 여러 컨테이너로 분리

예시

- Frontend
- Backend
- Database

## 장점

- 유지보수 쉬움

- MSA 구현 가능

# Docker Compose

## Docker Compose란?

여러 개의 컨테이너를 하나의 YAML 파일로 관리하는 도구

파일명

```text
docker-compose.yml
```

---

## Docker Compose 장점

- 여러 컨테이너 동시 실행
- 네트워크 자동 생성
- 볼륨 자동 연결
- 환경 변수 관리
- 실행 명령 단순화

---

# 핵심 정리

- ENV는 실행 환경 설정을 위한 변수이다.
- ARG는 이미지 빌드 시에만 사용된다.
- 컨테이너는 삭제되면 데이터도 삭제된다.
- 데이터를 유지하려면 Volume 또는 Bind Mount를 사용한다.
- Volume이 Docker에서 권장하는 방식이다.
- 기본 Bridge Network는 IP 통신만 가능하다.
- 사용자 정의 Network에서는 컨테이너 이름(DNS)으로도 통신 가능하다.
- Docker Compose는 여러 컨테이너를 하나의 YAML 파일로 관리하는 도구이다.
- 가장 많이 사용하는 Compose 속성은 services, build, image, ports, environment, volumes, depends_on이다.
- `docker compose up -d`로 실행하고 `docker compose down`으로 종료한다.
- 개발(Local), 테스트(Dev), 운영(Prod)은 Compose 파일을 분리하여 관리하는 것이 일반적이다.
